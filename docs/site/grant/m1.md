## Criterion 2: packages build and pass their tests

> `cip56-token` and `bridge-core` packages build and pass their unit + integration test suites against
> Canton mainnet, reproducibly from the repo.

### Build and test from source

Requires Daml SDK 3.4.8.

```bash
git clone https://github.com/ChainSafe/canton-erc20 && cd canton-erc20
git checkout v2.1.1           # the version vetted on MainNet and pinned by canton-middleware
./scripts/build-all.sh --daml-only
./scripts/test-all.sh
```

### Test run in CI

canton-erc20 CI ([canton-erc20#47](https://github.com/ChainSafe/canton-erc20/pull/47)) builds the packages and runs
the Daml Script suites. The [run](https://github.com/ChainSafe/canton-erc20/actions/runs/41858821253) is on
v2.1.1's Daml code with the workflow added on top (no Daml changes): all 18 test scripts pass, and the run
summary lists the four package IDs, which match the MainNet table above.

### Why not on DevNet or MainNet

These are unit tests for Daml Script's test ledger, which starts empty and lets tests set the time. On a live
participant they would collide on party names and leave permanent test parties and contracts. They would
also add nothing: CI tests the same package IDs that MainNet runs, and the deployed packages are exercised on
MainNet through the middleware ([recorded transfer](./m2#recorded-transfer-on-the-current-release)).
