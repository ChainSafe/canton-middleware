# M2: Middleware service (Ethereum JSON-RPC API)

Claim: [canton-dev-fund#921](https://github.com/canton-foundation/canton-dev-fund/issues/921)

All commands below run against the public MainNet endpoint and need no credentials.

```bash
RPC=https://middleware-api-prod1.02.chainsafe.dev/eth
call() { curl -s -X POST "$RPC" -H 'Content-Type: application/json' \
  -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"$1\",\"params\":$2}"; echo; }
```

## Criterion 1: stock MetaMask transfer on MainNet

> A stock MetaMask wallet connects to the middleware and completes an ERC-20 transfer against a CIP-56
> token (USDCx) on MainNet through the `eth_*` surface, with no bespoke client integration.

The steps are in [Get started](/get-started).

```bash
call eth_getTransactionReceipt '["0x0ef8e36bfa026cd9848efc694585de41a40d7054dd17019070fd2b2df35a9afb"]'
```

decimals), and `"cantonUpdateId": "1220ad02…11aa2"`. Receipts include `cantonUpdateId` for transfers made
on v0.10.0 or later.

## Criterion 2: EVM-shaped responses and onboarding on a live endpoint

> The documented `eth_*` / `net_*` / `web3_*` methods return EVM-shaped responses, and end-to-end
> onboarding (EIP-191 registration → external-party allocation → JWT session) works against a live
> endpoint.

**Methods.** The supported methods are listed in the [API guide](/middleware/API_DOCUMENTATION).

```bash
call eth_chainId '[]'           # "0x44d998be"
call web3_clientVersion '[]'    # "canton-middleware/v0.10.0-13b07ac…" (release and commit)
call eth_blockNumber '[]'       # hex block number
# DEMO totalSupply(): 1000 * 10^18
call eth_call '[{"to":"0xde30000000000000000000000000000000000001","data":"0x18160ddd"},"latest"]'
```

**Onboarding.** Registration (EIP-191) and party allocation run through the reference dApp, as in
[Get started](/get-started). The SIWE session endpoints are public:

```bash
curl -s https://middleware-api-prod1.02.chainsafe.dev/.well-known/jwks.json
curl -s "https://middleware-api-prod1.02.chainsafe.dev/auth/nonce?address=<your address>"
```
